## Phase 1 · 清理（不改动业务代码，只做归位与防护）

### 1.1 落 `.gitignore`（**第一步，先于 git init**）

```bash
cd <你的工作目录>/cc-haha-android
cp docs/open-source/templates/.gitignore .gitignore
cat .gitignore | head -30
```

**验收**：`.gitignore` 存在且含 `build-env/`、`*.pkg`、`*.apk`、`node_modules/`、`runtime/upstream/`。

### 1.2 归位调试脚本（可选但推荐）

```bash
mkdir -p tools/debug
# 先列出将移动的文件，人工确认后再执行（涉及文件移动，请自行核对）
ls runtime/*.mjs
# 确认无误后：
#   git mv 在未建仓时不可用，直接 mv 即可
mv runtime/cdp-*.mjs runtime/wstest.mjs runtime/e2e-session-test.mjs runtime/test-upgrade.mjs tools/debug/ 2>/dev/null
```

**验收**：`ls runtime/*.mjs` 无散落调试脚本；`tools/debug/` 内有对应文件。
**回退**：`mv tools/debug/*.mjs runtime/`

### 1.3 补 `tools/check-secrets.mjs`

新建密钥扫描脚本（Node 24 已就绪，无需额外依赖），并在 `.git/hooks/pre-commit` 挂载：

```bash
# 建仓后执行（Phase 2 之后）
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
node tools/check-secrets.mjs || { echo "❌ 检出疑似密钥，提交已阻止"; exit 1; }
EOF
chmod +x .git/hooks/pre-commit
```

**验收**：`git commit` 时若暂存区含 `sk-xxxxx` 形态字符串，提交被阻止。

### 1.4 补 `tools/fetch-upstream.mjs`（若 D1 选 B）

用途：替代把 `runtime/upstream/` 入库。要求：

```
☐ 支持指定固定 commit/tag（默认写死一个经过验证的 commit，保证可复现）
☐ 下载后校验（大小或 SHA256）
☐ 内附提示："使用者需自行确认上游代码的授权状态"（与 01 §2.3 呼应）
☐ 在 README 的构建步骤中列为第一步
```

**验收**：删除 `runtime/upstream/` 后，执行该脚本可重建（⚠️ 本机 GitHub 不通，需先用镜像或离线包验证；若无法验证，标注为**未验证项**并写入 README）。

## Phase 2 · 建仓与首次提交

```bash
cd <你的工作目录>/cc-haha-android

# ① 初始化（main 分支）
git init -b main
git config user.name  "<你的名字>"
git config user.email "<你的邮箱>"

# ② 预演：确认入库范围
git add -A --dry-run | wc -l                 # 预期 < 500
git add -A --dry-run | grep -E "\.pkg$|\.apk$|node_modules|/build/"   # 预期：无输出

# ③ 正式暂存
git add -A
git status --short | wc -l

# ④ 密钥扫描（Phase 1.3 的脚本）
node tools/check-secrets.mjs && echo "✅ 通过"

# ⑤ 首个提交
git commit -m "chore: 初始化仓库（cc-haha Android 全量版移植）"

# ⑥ 体检
git count-objects -vH                        # size-pack 预期 < 20 MB
git ls-files | wc -l                         # 文件数
git ls-files | grep -c "runtime/upstream/" || echo "✅ upstream 未入库"
```

**验收**：
- `size-pack` < 20 MB
- `git ls-files | grep -c "runtime/upstream/"` 结果为 0（若 D1 选 B）
- `git log --stat --oneline` 中无大体积文件

**回退**（仅在**尚未推送**时安全）：
```bash
rm -rf .git && # 重新执行本 Phase（.git 尚未推送，删除不会影响任何远程）
```

## Phase 4 · 推送与仓库配置

### 4.1 推送到 GitHub（本机不通时的三种通道）

```bash

# 通道 A：SSH over 443（部分网络环境可通）
#   ~/.ssh/config:
#     Host github.com
#       Hostname ssh.github.com
#       Port 443
#       User git
git push -u origin main

# 通道 B：使用代理
#   git config --global http.proxy http://127.0.0.1:<port>
#   git config --global https.proxy http://127.0.0.1:<port>

# 通道 C：Gitee 镜像先落地，再择机同步到 GitHub（推荐，见 D4）
```

## Phase 5 · 首个 Release

```bash
# ① 对齐三套版本号（见 03 §7.1）
#   android/app/build.gradle.kts → versionName / versionCode
#   RUNTIME_VERSION（改了 runtime/ 则必须 +1）

# ② 换正式签名（P1-1）
#   keytool -genkeypair -v -keystore ../keys/cc-haha-release.keystore \
#     -alias cc-haha -keyalg RSA -keysize 4096 -validity 10000
#   ⚠️ keystore 存放在仓库之外并离线备份；改 build.gradle.kts 的 signingConfig

# ③ 构建
./build-apk.sh

# ④ 真机验收（P1-13）
#   adb install -r android/app/build/outputs/apk/release/app-release.apk
#   冷启动 → 打开工作台 → 完成一次完整对话 → 记录机型/版本/日志

# ⑤ 校验与产物
mkdir -p dist && cp android/app/build/outputs/apk/release/app-release.apk \
   dist/cc-haha-android-vX.Y.Z.apk
cd dist && sha256sum *.apk > SHA256SUMS && cat SHA256SUMS

# ⑥ 打 tag 并推送
cd .. && git tag -a vX.Y.Z -m "cc-haha Android vX.Y.Z" && git push origin vX.Y.Z

# ⑦ 网页创建 Release，上传 dist/ 下的产物与 SHA256SUMS
#   Release Notes 用 03 §7.3 的模板
```

**验收**：
- `apksigner verify --print-certs` 显示你的证书指纹（非 debug）
- Release 页面含 APK + SHA256SUMS
- README 的下载链接指向该 Release
- 真机完整对话跑通（这是本项目"可用"的最终判据）

## 失败回退速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `git add` 后 `status` 出现 `*.pkg` | `.gitignore` 未生效或路径不匹配 | 检查 `.gitignore` 是否在仓库根；`git check-ignore -v <file>` 定位 |
| 提交体积 > 100MB | 大文件入库 | **未推送**：`rm -rf .git` 重来；**已推送**：`git filter-repo --path <file> --invert-paths` + `push --force` |
| 推送被 GitHub 拒绝（文件过大） | 单文件 > 100MB | 同上；改用 Release 附件 |
| GitHub 连接超时 | 网络约束 | 走 Phase 4.1 的通道 A/B/C |
| `build-apk.sh` 失败于 Gradle 仓库 | 全局镜像与 `FAIL_ON_PROJECT_REPOS` 冲突 | 用 `PREFER_SETTINGS` 模式（见 03 §8） |
| 真机装不上新 APK | 签名不一致 | 卸载旧版（注意会清数据）或用同一 keystore 签名 |
